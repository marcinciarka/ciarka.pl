Aurora, on-chain

The moving sky behind ciarka.pl is drawn live in your browser, and every visitor gets a different one. You can keep yours as a collectible (an NFT on Base), stored whole on the blockchain so it needs no server of mine.

In short

The moving sky on ciarka.pl is drawn live from one random number, so every visitor sees a different sky and can keep it as an NFT on Base. I wanted the picture itself stored on the blockchain, so a sky never depends on a server I run. Storage there is paid by size, so every picture has to fit in 16 kB. The contract enforces that limit and the collection rules, because it is the one part nobody can bypass. I designed it and made the key calls, and AI coding agents wrote much of the code. Eight skies have been minted, each for 6 to 9 US cents in fees.

Chapter 1

Every visitor gets a different sky

The sky at the top of ciarka.pl is drawn live by your browser. One random number decides its shape, its motion and its two colours.

A small program on your graphics card draws the sky, with no 3D library. There are about 4.3 billion possible numbers, and the same number always gives the same sky. So a link with a sky's number in it shows that sky to anyone.

How one number becomes a sky

A raw WebGL fragment shader, with no three.js. The drawing buffer stops at 800 device pixels tall and the pixel ratio is capped at 2. CSS stretches the canvas to the viewport. A resize only reallocates the buffer when the ideal size drifts more than 15%, because a phone's URL bar would otherwise restart the sky on every scroll. On a 375 x 844 box, a 60 px toolbar shift moved the buffer from 355 x 800 to 375 x 784.

The seed is a uint32. It goes through mulberry32 and comes out as a noise offset, an animation phase and two distinct colours from a five-colour palette. The offset and phase are drawn first, so seeds from before the palette existed keep the exact sky they had. A test pins those values byte for byte. The seed lives in localStorage. A ?seed=N link is never saved, so following a shared link does not replace your own sky.

Source: src/lib/seed.ts, src/lib/aurora.ts. Tests: src/lib/seed.test.ts ("is deterministic for the same seed", "keeps x/y/t byte-identical to the pre-palette implementation", "picks two distinct palette colors for every seed"), src/lib/aurora.test.ts (render-size policy).

Chapter 2

The picture is stored inside the contract

Most NFTs hold only a link to an image on another server. If that server goes away, the NFT points at nothing. Each Aurora sky keeps its picture inside the contract itself.

I wanted a sky to last as long as the blockchain does. So each collectible holds two things: the picture and the number that produced it. When a marketplace asks for a collectible, the contract builds its description on the spot from those two things. Nothing about a sky is stored anywhere else.

The contract has no owner and no admin functions. After deployment nobody can change its rules, me included.

What the contract stores and returns

AuroraSky keeps two mappings per token: the raw WebP bytes and the uint32 seed. tokenURI() assembles OpenSea-style JSON on every read, with the image embedded as a data:image/webp;base64 URI and the seed as an attribute and as an external_url back to https://ciarka.pl/?seed=N. contractURI() returns EIP-7572 collection metadata as an on-chain data URI too. It leaves out a collection image on purpose, because there is no on-chain one to embed and a hosted URL could rot.

Every mint emits SkyMinted(tokenId, minter, seed), so an indexer can map token to seed from logs alone. There is no ERC-2981 royalty interface. The NatSpec says this was considered and rejected for a free drop. The site is static files on GitHub Pages behind Cloudflare.

The contract was deployed with CREATE2 at a mined vanity address, 0xc1aC1ac1Ac54691F6a22e2272ABA6f8989bd119a, which is the same on Base Sepolia and Base mainnet. Mainnet deploy block: 49,453,995 (2 August 2026).

Source: contracts/src/AuroraSky.sol. Tests: test_TokenURIContainsMetadata and test_ContractURIContainsMetadata decode the base64 JSON and check its fields. forge-std only ships base64 encoding, so the test file carries a small decoder.

Chapter 3

Every picture has to fit in 16 kB

On a blockchain, storage is paid by size, and the visitor pays the fee. So the size of the picture sets the price of a sky. I capped every picture at 16 kB, about 1.5 times the largest sky minted so far.

Before any contract code existed, I had a small cost model built to see which picture sizes were affordable. The written plan the AI agents worked from did not let contract work start until I had reviewed those numbers. Checked against the eight mints on Base, the model was within 4% every time.

The page takes the picture from the sky on your screen, in a compact image format (WebP). It lowers the quality step by step until the picture fits, and stops before the colours band. In that one frame it brightens the stars, so they survive as a small thumbnail.

The cost model and what the mints measured

Cost model (scripts/estimate-mint-cost.mjs): a fixed 100,000 gas for the mint plus 22,100 gas per 32-byte slot of image. At the 16,000-byte cap that is 500 slots and about 11.15M gas.

Test mint before launch: on Base Sepolia, a 512 px WebP of about 4 kB cost 0.000023849 ETH, about $0.044 at 0.0072 gwei, roughly 3.31M gas with the L1 data fee included. The model had predicted about 2.9M gas of execution.

Gas prices were 0.0050 to 0.0078 gwei. The L1 data fee was 0.00000003 to 0.00000024 ETH per mint, under 1% of each fee, which is what the cost report expected after EIP-4844. The model leaves out the transaction's base cost and the cost of sending the picture as calldata. That likely accounts for most of the steady 3.3 to 3.6% gap.

Capture (captureFrame() in src/lib/aurora.ts): it copies the right-hand square of the live canvas, up to 800 px, because the hero text sits on the left. It encodes WebP at quality 0.85, then 0.75, then 0.65, and stops at the first one under 16,000 bytes. Below 0.65 the gradients band. For that one draw it sets the star boost to 1.6, tuned against a 160 px downscale: below about 1.4 the stars wash out, above about 1.8 they look like dots at full size. The boost is set, drawn, copied and reset in one synchronous task, so no frame on screen ever shows it.

Safari: toDataURL("image/webp") silently returns a PNG. The capture checks the encoder's output and returns nothing if it is not WebP (isWebpDataUrl), and supportsWebpCapture() lets the panel explain this before any capture. The first cost report planned a 256 px snapshot and a 64,000-byte cap, on a "PNG is 5 to 15 times larger" estimate nobody had measured.

Source: scripts/estimate-mint-cost.mjs, src/lib/capture.ts, src/lib/aurora.ts, docs/superpowers/plans/aurora-nft-cost-report.md.

Chapter 4

How a sky becomes a collectible

Six steps take a sky from your screen to the blockchain. The size limit is checked three times on the way. The contract checks last, because it is the only check nobody can skip.

  1. Your browser draws the sky.
  2. A number picks which sky it is.
  3. The page takes a picture of the sky on your screen.
  4. The page checks the 16 kB limit before any wallet is involved, so a visitor never sees a mint button that would fail.
  5. The contract checks the limit again, enforces the collection rules and stores the picture with its number.
  6. Marketplaces and my gallery read the picture back.

When a sky is minted, the contract briefly hands control to the receiving wallet, and that wallet can be a program. The contract records that the wallet has minted before the hand-off. So a hostile program cannot use that moment to mint a second sky. A test plays the hostile program and checks that it fails.

How the three size checks and the mint rules are wired

Size checks. The mint panel checks right after capture. validateSnapshot runs first in both estimateMint and mintSky in src/lib/mint.ts, before any wallet or network access, so the mint library is safe to call without the UI. It checks WebP first, then size. Tests pin that order ("throws ImageTooLargeError before touching the network", "throws WebpRequiredError before the size guard"). The contract reverts with ImageTooLarge above MAX_IMAGE_BYTES = 16_000, and test_MintExactMaxSizeSucceeds mints exactly 16,000 bytes.

Mint rules. mint(bytes image, uint32 seed) checks, in order: SoldOut (MAX_SUPPLY = 100), WalletAlreadyMinted (hasMinted), EmptyImage, ImageTooLarge and SeedAlreadyMinted (seedMinted). Both flags are set before _safeMint, because _safeMint calls onERC721Received on a contract recipient. That is the reentrancy window. test_ReentrantSecondMintReverts uses a MaliciousReceiver that mints again from the callback and asserts the second mint reverts. test_TransferKeepsSeedMinted checks that a transfer does not free the seed.

Pre-checks. checkMintable reads seedMinted and hasMinted with Promise.allSettled. With Promise.all, one failed RPC read would reject the whole call, the caller would fall back to "ok", and a known "this seed is taken" answer would be lost. Now only a double failure falls back to "ok", and the contract still has the last word. Tests: "reports seed-taken even when the hasMinted read fails", "degrades to ok only when both reads fail".

Read paths. Marketplaces call tokenURI(). The on-site gallery reads imageOf and seedOf in two multicalls, 15 tokens a page, which fills three rows of the five-column grid. A page is roughly 135 kB of on-chain image. Pages are cached until a new mint shifts every page by one. All reads share one viem client with a fallback transport over six public Base RPCs, because mainnet.base.org was returning 429s under load.

Seed limit. The NatSpec on mint() says the seed-to-image binding is unverified on-chain by design. Anyone calling mint() directly can pair any WebP under the cap with an unused seed.

Chapter 5

A timer bug could have minted the wrong sky

A mint cannot be undone, so the picture and its number must always match. A timing bug could have paired a picture of one sky with the number of another. The fix makes the page wait for the sky itself.

Visitors can ask for a new sky, and the old one fades out over about a second. The page used to wait a fixed time for that fade before taking the picture. But the animation pauses when you switch tabs, and the timer kept running. So the page could take a picture of the old sky and label it with the new sky's number. On the blockchain that mistake is permanent.

Now the animation reports when the fade has finished, and the page waits for that signal. A paused animation just means a longer wait.

The three guards that keep picture and number paired

The "try another aurora" flow in MintPanel used to wait setTimeout(FADE_MS) before capturing. The crossfade runs on the renderer's pause-adjusted clock (FADE_SECONDS = 1), which stops when the hero leaves the viewport or the tab is hidden. A wall-clock timer could expire while the fade was frozen at its first frame. Now the renderer exposes onceSettled, registered in skyStore as whenSkySettled, and the flow reseeds first, then waits on it.

Guard 1: MintPanel captures the seed and the snapshot once and carries both through the flow. It never reads the seed again at mint time.

Guard 2: skyStore holds a mint-active flag that disables "new sky" while the mint segment is open. Only that segment sets it, so browsing the gallery leaves the sky free.

Guard 3: captureFrame() returns nothing mid-crossfade, because a blend of two skies is not any one seed's image. Callers wait for onceSettled, and this makes it impossible to mint the blend if one does not.

Tests: src/lib/skyStore.test.ts ("mint-active flag (seed-provenance guard)", "whenSkySettled": "delegates to the registered renderer instead of firing itself").

Chapter 6

Tests and eight live mints back the numbers

Sixteen contract tests check every rule the collection depends on. Eight of 100 skies have been minted so far.

The contract has been live on Base since 2 August 2026. All eight mints came in the first week, the last on 7 August. Two minted skies, at 10 kB and 10.5 kB, are larger than the 9 kB picture in the contract's gas test. The 16 kB limit still has room. The Safari message is covered by tests only, and I have not checked it on a real Safari.

What each test suite covers

Foundry (contracts/test/AuroraSky.t.sol, 16 tests, all passing on 17 November 2026): name and symbol, mint assigns the token, tokenURI and contractURI JSON fields, sold out at 100, second mint from one wallet, reentrant mint from a malicious receiver, duplicate seed from a different wallet, empty image, oversized image, an image of exactly 16,000 bytes, the gas ceiling, tokenURI for a missing token, a transfer that keeps its seed taken, the getters, and the SkyMinted event.

The gas test (test_MintRealisticPayloadGas) mints a 9,000-byte payload, which costs 6,444,817 gas, and fails above 6.8M. Its ceiling started at 3.6M for a 4,700-byte image. It moved when the capture became the live canvas at up to 800 px with the star boost. Six captures at 1280 x 800 then measured 7,998 to 9,657 bytes. Mainnet mints 4 and 6 stored 9,962 and 10,508 bytes, and used 7.22M and 7.61M gas.

Vitest (the whole site suite is 274 tests in 24 files, all passing on 17 November 2026; the Aurora files are seed, capture, aurora, mint, mintConfig, skyStore, pageCache and mintedTotal). The WebGL context and the canvas encoder are browser-only and are not in the Node suite. The policy around them is:

  • seeds are deterministic, and the offset and phase stay byte-identical to the version before colours existed;
  • the snapshot guards throw before any wallet or network access, WebP check first;
  • checkMintable keeps a known verdict when the other read fails;
  • the bigint USD math, the cost formatter, gallery paging and the page cache;
  • the render-size policy, including a phone's URL bar not reallocating the buffer;
  • the mint-active flag and whenSkySettled in skyStore.

Deterministic still: scripts/aurora-still.html imports the shader and seed.ts instead of copying them, and draws one frame at a fixed seed and time. Same seed, byte-identical WebP. scripts/aurora-still.test.mjs checks the file exists, is a WebP and stays under 50,000 bytes.

On-chain check: token 1 was minted in transaction 0xc1f41cc34f158406343f3844ac9f748677a97bb89ab8f12461bdd0c69e489f7f (block 49,458,324).

Six decisions and what each cost

Each row is a choice with a reasonable alternative. Read across for the trade-off, or open a row for the reasoning and the evidence.

The questionWhat I choseWhat I passed onWhat it cost
  • Where should the picture live? What I choseInside the contract, next to its number. What I passed onA link to a hosting service, as most NFTs use. What it costEvery byte costs the visitor a fee, so the picture's size sets the price.

    My site is static files, so there is no server to hand out NFT data. A hosting service would be one more thing that has to keep running for a sky to exist. Storing the picture in the contract made size the main constraint of the project, and I accepted that.

    Evidence

    contracts/src/AuroraSky.sol (tokenURI, contractURI); test_TokenURIContainsMetadata; deep note in Chapter 2.

  • Which browsers can mint? What I choseOnly browsers that can make WebP pictures. Others get an explanation instead of a mint button. What I passed onA PNG fallback for Safari, with a 64 kB limit. What it costSafari visitors can see the sky but cannot mint it.

    Safari returns a PNG when asked for WebP, and a PNG might be many times larger. The first plan bent around a 5 to 15 times estimate nobody had measured. Dropping the PNG path let the limit fall to 16 kB, so every mint stays small and cheap.

    Evidence

    src/lib/capture.ts (isWebpDataUrl, supportsWebpCapture); src/lib/capture.test.ts ("rejects png data urls (Safari fallback)"); docs/superpowers/plans/aurora-nft-cost-report.md.

  • Where is the size checked? What I choseThree places: the mint panel, the mint code and the contract. What I passed onThe contract alone, or the website alone. What it costThree checks to keep in step, with tests pinning their order.

    The panel checks first, so a visitor never sees a mint button that would fail. The mint code checks again, so it is safe to use on its own. The contract checks last, because it is the only check nobody can skip.

    Evidence

    src/lib/mint.ts (validateSnapshot); src/lib/mint.test.ts ("estimateMint guard ordering", "mintSky size guard"); test_RevertsOnOversizedImage, test_MintExactMaxSizeSucceeds.

  • Who enforces the collection rules? What I choseThe contract: one sky per number, one per wallet, 100 in total. What I passed onWebsite-only checks, and proving that a picture matches its number. What it costSomeone calling the contract directly can pair any small WebP with an unused number.

    Anyone can call the contract without my website, so the rules have to live there. The number records where a picture came from, but the contract cannot check that the picture matches it. Redrawing the sky inside the contract to prove the match would cost far too much. For a free drop of 100 skies I accepted that limit and wrote it into the contract's documentation.

    Evidence

    test_SecondMintFromSameWalletReverts, test_RevertsOnDuplicateSeed, test_ReentrantSecondMintReverts, test_MintRevertsWhenSoldOut; NatSpec on mint() in contracts/src/AuroraSky.sol.

  • How do the picture and its number stay paired? What I choseFreeze both at the start, lock "new sky" during a mint, and wait for the fade to finish. What I passed onReading the number again at mint time, and waiting on a fixed timer. What it costTwo extra signals to maintain in the shared sky state.

    The contract cannot check the pairing, so the page is the only thing keeping it right, and a mistake is permanent. The timer version could capture the old sky with the new number when the tab was hidden. Waiting on the animation itself removes that timing gap.

    Evidence

    src/lib/skyStore.ts (setMintActive, whenSkySettled); src/lib/skyStore.test.ts; captureFrame() in src/lib/aurora.ts; Chapter 5.

  • Who downloads the wallet code? What I choseOnly visitors who open the mint panel. What I passed onShipping the wallet library to every visitor with the rest of the page. What it costOne small settings file must stay import-free by hand, or the wallet code leaks into the first load.

    Most visitors never mint, so the wallet library should not cost them anything. The on-demand wallet code is about 92 kB compressed, a bit more than the 83 kB of JavaScript every visitor downloads. The price estimate shows dollars when the price feed answers and still shows the fee in ETH when it does not.

    Components in the entry chunk read the address, the cap and the page size from contractAddress.ts. mintConfig.ts needs viem/chains, so it re-exports the address from there instead of defining it, and only code behind import("../lib/mint") touches it. The estimate runs estimateContractGas, getGasPrice and the Chainlink ETH/USD latestRoundData read in parallel, and the oracle read fails to null on its own. The feed's 8 decimals are hardcoded to save a round trip. The USD math is bigint throughout and floors like Solidity does. The formatter keeps up to 8 decimals and shows <0.00000001 instead of a misleading 0.000000.

    Evidence

    src/lib/contractAddress.ts (imports nothing) and src/lib/mintConfig.ts (re-exports the address); src/lib/mint.test.ts ("estimateMint totalUsd": "degrades to null when the oracle read throws"). Sizes from vite build of commit 6979317: mint 5.3 kB, _esm 42.4 kB, ccip 31.4 kB, secp256k1 11.9 kB and utils 1.0 kB gzipped on demand, against main at 82.9 kB gzipped.

What I would change

Measure the picture before writing the numbers down. The gas test started at 4,700 bytes and had to move to 9,000 when the capture changed. The limit held because it had margin, but the test was guarding a picture size that no longer existed. Two minted skies are now larger than its 9 kB. Next time I would tie the test to measured pictures from the start.

Settle the policy before modelling it. A full round of the cost report went into a Safari PNG fallback that I dropped the same day. Deciding "WebP or nothing" first would have saved it.
