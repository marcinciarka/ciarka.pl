Aurora, on-chain

The sky behind ciarka.pl is a shader driven by one seed. You can mint the sky you are looking at as an ERC-721 on Base, and the image itself is written into the contract's storage.

The constraint

Most NFT images live on IPFS or behind a metadata server, and the token holds a link to them. I wanted the token to be the image. This site is static files on GitHub Pages, so there is no backend to serve metadata from, and I did not want a pinning service to be one more thing that has to keep running for a sky to exist.

So AuroraSky stores two things per token: the raw WebP bytes and the uint32 seed that shaped the sky. tokenURI() assembles the OpenSea-style JSON on every read, with the image embedded as a data:image/webp;base64 URI. contractURI() does the same for the collection page. Nothing about a token lives off-chain.

That choice sets every other number on this page. Contract storage is paid per 32-byte slot. My cost model in scripts/estimate-mint-cost.mjs is a fixed 100,000 gas for the mint plus 22,100 gas per slot of image. The size of the image is the price of the mint, so the whole project turns into a byte budget.

Before writing the contract I ran that model as a decision gate, and later checked it against a real mint on Base Sepolia. The first mint stored a 512px WebP for a fee of 0.000023849 ETH, about $0.044 at 0.0072 gwei, roughly 3.31M gas including the L1 data fee. The model had predicted about 2.9M gas of execution for a 4 kB image. That was close enough to size everything else with it.

How it fits together

The pipeline runs in one direction: a seed picks a sky, the visitor's own canvas becomes the image, the image has to pass a size gate, and the contract keeps it. Reads come back out through two paths.

  1. Shader. A raw WebGL fragment shader, no three.js. The render buffer stops at 800 device pixels tall and the pixel ratio is capped at 2, because the sky is low-frequency noise and more pixels buy nothing visible. CSS stretches the canvas to the viewport.
  2. Seed. One uint32 goes through mulberry32 and comes out as a noise offset, an animation phase and two distinct colors from a five-color palette. Same seed, same sky. ?seed=N in the URL shows someone else's sky without overwriting yours.
  3. Capture. captureFrame() copies the right-hand square of the live canvas, up to 800px, because the hero text sits on the left. It is the sky on screen, not a re-render. For that one draw it boosts the stars by 1.6 so they survive as a 160px marketplace thumbnail. It encodes WebP at quality 0.85 and steps down to 0.75 and 0.65 until the frame fits. Below 0.65 the gradients start to band.
  4. Gate. 16,000 bytes of decoded WebP, checked three times. More on that below.
  5. Contract. mint(bytes image, uint32 seed) checks supply, wallet, empty image, size and seed, then stores the bytes and the seed and emits SkyMinted so indexers can map token to seed from logs alone. There are no owner functions and no royalty interface.
  6. Read paths. Marketplaces call tokenURI(). The on-site gallery reads imageOf and seedOf in two multicalls, 15 tokens a page, which fills three rows of the five-column grid. A page is roughly 135 kB of on-chain image, so pages are cached until a new mint shifts them all by one.

Five decisions

Each of these had a reasonable alternative. This is what I picked, what I passed on, and why.

1. WebP or nothing, and a cap that came down from 64,000 to 16,000 bytes

Chose
Mint only WebP. If the browser cannot encode it, there is no mint and the visitor is told why.
Passed on
A PNG fallback for Safari, with a smaller snapshot and a cap sized for PNG.

Safari ignores toDataURL("image/webp") and silently returns a PNG. My first cost report planned around that: a 256px snapshot and a 64,000-byte cap, because a PNG might be 5 to 15 times larger than the WebP and a large one at 512px could exceed a 30M-gas block. That 5 to 15 range was an estimate I had never measured, and the plan was bending around it.

So I dropped the PNG path the same day. The capture checks what the encoder actually produced, not what it asked for, and returns nothing if it is not WebP. With no PNG to make room for, the cap fell to 16,000 bytes. Under the model that is about 11.15M gas in the worst case, roughly 37% of a 30M block. The cost is that Safari visitors can look at the sky but cannot mint it.

2. The same size check in three places

Chose
Check the cap in the mint UI, again in estimateMint and mintSky, and revert in the contract.
Passed on
Trusting the contract alone, or the UI alone.

Each check has a different job. The UI check runs right after capture, before any wallet is involved, so an oversized frame never gets a mint button. validateSnapshot runs first thing in both estimateMint and mintSky, before any network access, so the mint library is safe to call without going through the UI. Tests pin that ordering. The contract's ImageTooLarge revert is the only check nobody can skip.

The real payload changed later. Once the capture became the live canvas at up to 800px with the star boost, six captures at 1280x800 measured between 7,998 and 9,657 bytes. A Foundry test mints a 9,000-byte payload, which costs 6,444,817 gas, and fails above 6.8M. The cap stays about twice the largest capture I measured.

3. One sky per seed and one mint per wallet, enforced in the contract

Chose
seedMinted and hasMinted mappings, plus MAX_SUPPLY = 100, all checked in mint().
Passed on
Client-side checks only, and verifying on-chain that the image matches the seed.

Anyone can call the contract directly, so the rules that define the collection have to live there. Both flags are set before _safeMint, because _safeMint calls back into a receiving contract. A test uses a malicious receiver that tries to mint again from that callback and asserts it fails.

The client reads both guards before offering a mint. It uses Promise.allSettled, not Promise.all, so one failed RPC read cannot hide a known "this seed is taken" answer from the other. Only a double failure degrades to "go ahead", and then the contract still has the last word.

What the contract does not do is prove that the image came from the seed. It cannot re-run a WebGL shader at any reasonable cost. The stored image is the artifact and the seed is provenance metadata. I wrote that down in the contract's NatSpec rather than leave it implied.

4. Keeping image and seed honest while a mint is open

Chose
Freeze seed and snapshot together once, lock "new sky" while minting, and wait for the crossfade itself to finish.
Passed on
Reading the seed again at mint time, and waiting on a wall-clock timer.

Since the contract cannot check the pairing, the client is the only thing keeping it right, and a mistake is permanent. If a visitor asks for a new sky during a mint, a naive flow sends image A with seed B.

There are three guards. MintPanel captures the seed and the snapshot once and carries both through the flow. skyStore holds a mint-active flag that disables "new sky" while the mint segment is open, and only that segment sets it, so browsing the gallery leaves the sky free. And captureFrame() returns nothing mid-crossfade, because a blend of two skies is not any one seed's image.

The bug I had to fix here was a timer. The "try another aurora" flow used to wait setTimeout(FADE_MS) before capturing. The fade runs on the renderer's pause-adjusted clock, which stops when the hero scrolls out of view or the tab is hidden, so the timer could fire while the canvas still showed the old sky. Now the renderer reports when the fade has landed (onceSettled), and a stopped clock just means waiting longer.

5. Wallet code off the first load, and a gas estimate in dollars

Chose
viem only behind import("../lib/mint"), a dependency-free address module, and a Chainlink-priced estimate that degrades to ETH only.
Passed on
viem in the entry bundle, and an estimate that fails if the price feed does.

Most visitors never mint, so the wallet library should not cost them anything. Components in the entry chunk read the address, the cap and the page size from contractAddress.ts, which imports nothing. mintConfig.ts needs viem/chains, so it re-exports the address from there instead of defining it, and only code behind the dynamic import touches it.

The estimate runs estimateContractGas, getGasPrice and the Chainlink ETH/USD latestRoundData read in parallel. If the oracle fails, the dollar row is empty and the ETH row still shows. The feed's 8 decimals are hardcoded to save a round trip, and the USD math is bigint throughout, flooring like Solidity does. Base gas puts a mint well under 0.000001 ETH, where toFixed(6) printed 0.000000, so the formatter keeps 8 decimals and shows <0.00000001 rather than implying the mint is free.

Reads go through one shared client with viem's fallback transport, because mainnet.base.org was returning 429s under load. Six public Base RPCs sit behind it.

Testing

Foundry. contracts/test/AuroraSky.t.sol has 16 tests. They cover the supply cap at 100, a second mint from one wallet, the reentrant mint, a duplicate seed from a different wallet, empty and oversized images, an image of exactly 16,000 bytes, the 9,000-byte gas ceiling, and a transfer that must not free its seed. The tokenURI and contractURI tests decode the base64 JSON and check its fields; forge-std only ships base64 encoding, so the test file carries a small decoder.

Vitest. The browser-only parts, the WebGL context and the canvas encoder, are not in the Node suite. The policy around them is:

  • Seeds are deterministic, and the noise offset and phase stay byte-identical to the version before colors existed, so an existing seed keeps the sky it always had.
  • The snapshot guards throw before any wallet or network access, WebP check first.
  • checkMintable keeps a known verdict when the other read fails.
  • The bigint USD math, the cost formatter, gallery paging and the page cache.
  • The render-size policy, including a phone's URL bar not reallocating the buffer.
  • The mint-active flag and whenSkySettled in skyStore.

Deterministic stills. The image at the top of this page comes from scripts/aurora-still.html, which imports the real shader instead of a copy and draws one frame at a fixed seed and a fixed time. Same seed, byte-identical WebP. A test checks the file exists, is a real WebP and stays under 50,000 bytes, since it is generated outside the normal build and nothing else would notice it going missing.

What I would change

Measure the payload before writing the numbers down. The gas test's ceiling started at 3.6M for a 4,700-byte image and had to move to 6.8M and 9,000 bytes when the capture changed. The cap held because it had margin, but the test was guarding an image size that no longer existed. It is now tied to measured captures, which is where it should have started.

Settle the policy before modelling it. A full round of the cost report went into sizing for a PNG fallback that was later dropped. Deciding "WebP or nothing" first would have saved that.

Know the limit of the seed. The seed is provenance, not proof. Someone calling mint() directly can pair any WebP under the cap with an unused seed. For a free, personal drop of 100 skies I accepted that, and the contract says so.
